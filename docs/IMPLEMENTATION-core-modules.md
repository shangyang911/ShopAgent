# 三个核心模块实施说明

对应 `PRD-core-modules-v1.md` 的 P0 范围。默认库存阈值采用建议值 5 件，可在库存中心修改；超时未发货采用确认收款后满 24 个自然小时。单店、单仓、人民币，沿用现有管理员权限。

## 页面入口

- `/`：经营概览。今日、昨日、近 7/30 天、自定义日期，五项指标、日/周/月趋势、当前待办和带时间口径的订单下钻。
- `/products`：原商品管理。已有商品可售数量只读；新商品数量产生期初流水。
- `/inventory`：库存总览、库存流水、补货入库、低库存提醒。默认阈值、商品监控及专属阈值均可配置。
- `/orders`：订单工作台。保留创建订单，新增关键词、多状态、创建/付款/完成时间、金额、打印请求、超时及未知时间筛选，条件和页码写入 URL。
- 原客户和配送入口保留，配送页状态操作也调用统一业务服务并记录真实账号。

## 业务事务

- 创建订单：合并重复商品，按商品 ID 加锁，可售减少、预留增加，追加流水及创建事件。
- 确认收款：服务端读取订单应收金额，生成唯一收款事实及首次付款时间。一次全额确认，重复请求不重复记账；取消或标记退款不删除原收款。
- 开始配送：结束活动预留并出库，可售不重复扣减；配送完成只写完成时间和事件。
- 未出库取消或原流程退款：仅释放活动预留一次。出库后标记退款不会自动增加库存；不推算退款金额或退款时间。
- 补货：最多 100 个不同商品、重复商品合并，每种商品合并后为 1–1000000 件正整数；接口最多接收 1000 行后合并校验。先存草稿，再核对确认；所有商品一次入账。重复确认返回原结果。草稿可编辑或作废，已确认单据只读。
- 库存、预留、流水、收款及订单事件与对应业务动作同事务提交，提交失败全部回滚。
- MySQL 写操作使用一致的商品加锁顺序，并对关键去重记录执行当前读取，防止等待锁后的旧快照导致重复记账。
- 告警在库存、规则、商品可售状态变更时评估；同商品最多一个活动告警。已读不解除风险，库存严格大于阈值才恢复，0 是有效专属阈值。后台每 5 分钟补偿校验。

## 时间与金额

- 新业务时间由服务端生成并按 UTC 保存，API 明确输出 `Z`，页面及配货文档使用上海时区。
- 查询采用 `[start_at, end_at)`；接口拒绝无时区时间，界面日期的截止日转换为次日排他上界。
- 订单原表的历史时间保留原值，不直接迁移或假定其时区。`order_facts` 中历史创建、付款、配送、完成时间保持未知，界面明确标记；有可靠时间的记录优先排序，未知记录按 ID 稳定排序。
- 经营统计只使用已核实的创建/完成事实及结构化收款记录，显示完整事件数据覆盖起点。覆盖前显示未知，跨覆盖起点显示部分数据，零业务与无可靠数据区分。
- 同屏统计、趋势和下钻共用 `as_of`。当前待办独立于历史日期。今日及未结束区间对比前周期相同已过时长，完整区间对比前一等长区间。
- 后端金额使用 Decimal 和 Numeric；前端金额累计使用 BigInt 整数分，图形高度使用数字比例。平均订单金额无分母时显示 `—`。

## 配货单

- 批量限当前页、最多 50 单。首次仅待发货订单可生成；配送中和已完成只能补打已有文档；取消或退款阻止新请求。
- 任一订单冲突阻止整批生成，保留选择并显示冲突原因。已请求过打印的订单需填写补打原因。
- 文档保存商品、收件、专用配货备注、金额显示选项的不可变 JSON 快照及 SHA-256 摘要。普通内部备注不会自动印出。
- 区分“生成最新快照”和“补打此版本”。旧版本沿用内容与摘要；每次明确打印意图产生新请求记录，接口重试复用幂等键。
- A4 页面按浏览器实测尺寸分页，重复订单号及表头，计算每单页码/页数，长备注可续页，预留配货和复核签字区。使用默认 A4、100% 缩放，关闭浏览器额外页眉页脚。
- 浏览器取消对话框也只保留“请求打印”记录；不宣称实际出纸，不改变状态或库存。历史文档可单独查看，不产生新请求。

## 数据接入与启动

沿用原启动命令。启动时创建新增表，再执行幂等接入：

1. 保留 `products.stock` 当前值作为可售数量，不再次扣库存。
2. 为待付款、待发货订单的可识别商品建立活动预留，期初账面在库为当前可售加预留。
3. 每个已有商品建立期初流水，每个历史订单追加“历史数据接入”事件，保存接入时间，不编造历史动作。
4. 保存覆盖起点与默认阈值；重复启动不重复接入。

新增数据保存在 `operation_settings`、`order_facts`、`confirmed_receipts`、`order_events`、`inventory_reservations`、`inventory_movements`、`inventory_rules`、`inventory_rule_events`、`stock_alerts`、`inbound_receipts`、`inbound_receipt_lines`、`order_print_jobs`、`order_print_documents`。原订单和商品表无需删除或重建。

上线前仍需业务核对历史取消/退款异常、已删除商品的旧订单行，以及原无时区时间的含义；本次接入不能替代实物盘点或历史银行对账。未提供补录接口，可靠历史事实的补录应另做带来源、原业务时间、录入时间与操作者的受控流程。

## 验证

后端默认使用隔离 SQLite，包含业务事务、重复请求、告警生命周期、打印、日期统计与鉴权测试；可启用随机临时 MySQL 库执行真实并发测试：

```powershell
cd backend
$env:RUN_MYSQL_TESTS = '1'
.venv\Scripts\python.exe -m unittest discover -s tests -v
Remove-Item Env:RUN_MYSQL_TESTS
```

MySQL 测试只创建和清理随机命名的测试数据库，不写应用业务数据。

```powershell
cd frontend
npm test
npm run build
```

浏览器联调使用独立 SQLite 与端口 8002/5175，验证实际页面操作、下钻口径、补货、备注、打印及手机宽度。`backend/tests/run_smoke_server.py` 只接受显式 SQLite 配置。测试文件与截图位于被忽略的 `.local-test/`。

2026-10-27 本机验收结果：35 项后端测试全部通过（含 5 项真实 MySQL 并发测试），20 项前端测试及生产构建通过；浏览器完整操作链无页面运行错误。50 单批量单据生成 50 个独立页面；60 行各 180 字长商品名、长地址及长备注的压力单生成 10 页 A4，实测 PDF 页数与每单页码一致，页脚与正文无重叠。浏览器和打印测试数据均在独立 SQLite 中。

## 后续范围

本轮不启用退款金额/净确认收款指标，不接支付网关。热销排行等剩余 P1 未实施；供应商、多仓、盘点调整、退货验收和员工权限仍按 PRD 暂缓。P95 性能目标尚未在约定业务规模下做负载验收。

## 库存中心补齐（2026-10-28）

- 库存流水支持按当前商品、类型、关联单号、操作者及时间范围导出全部匹配记录，不受当前页限制；补货单支持全量明细 CSV 导出，包含草稿、已确认、已作废单据及发生时商品名称。入口为 `/api/inventory/movements/export` 与 `/api/inventory/inbounds/export`，均要求登录。
- CSV 使用带 BOM 的 UTF-8、标准 CSV 引号和 UTC 业务时间；对可能被表格软件当成公式的文本加前缀保护，带符号的数值变化保持数值。数据库分批读取，不导出内部幂等键或创建摘要。
- 补货入口只携带商品，不预填实际到货数量；草稿保存后展示服务端合并明细，再确认入账。读取已有单据失败时禁止保存，避免误建新单；客户端同时拦截重复保存、确认和作废请求。
- 已确认与作废单据直接显示单据名称快照，不查询当前商品名称进行替换；商品改名或删除后历史单据仍能识别。
- 库存流水全部筛选条件及提醒状态写入 URL，刷新后保留；阈值、告警生命周期、预留/出库/释放和打印库存规则沿用统一事务服务。

本次验证：41 项后端测试全部通过（含 6 项真实 MySQL 并发测试），26 项前端测试及生产构建通过。独立 SQLite 浏览器验收覆盖 `6→5→0→5→6` 告警生命周期、已读后保留风险、重复商品合并、已确认单只读、重复确认不增库存、改名后保留单据快照、两种 CSV 实际下载、刷新后保留流水筛选及 390px 手机宽度；无页面运行错误。浏览器脚本和截图位于 `.local-test/inventory-acceptance.mjs`、`.local-test/inventory-movements-verified.png`、`.local-test/inventory-stock-verified.png`，未写入应用业务库。

## 订单工作台补齐（2026-10-28）

- `/orders` 保留关键词、多状态、业务时间、金额、打印请求、历史未知时间及概览 `as_of` 联动。增加可见的近 30 天入口、字段级错误说明、筛选条件摘要、创建时间正/倒序；未选择日期时不会隐藏旧订单。选择时间待核实时清空日期与快照边界，手动填写日期则退出未知时间模式。
- 页码、每页 20/50 条、排序与详情 `order_id` 保存在 URL。正常点击进入详情，支持新标签页、刷新、浏览器前进后退及保留页码返回列表；改变筛选或翻页清空当前页选择并提示。详情及列表均丢弃过期响应。
- 时间线保留原事件、作者快照和业务时间。更正通过 `POST /api/order-operations/orders/{order_id}/events/{event_id}/corrections` 追加，要求内容和原因，引用原事件，并幂等去重；不修改库存、收款或原业务字段。新事件在 JSON 明细中补充结构化 `changed_fields`、`correlation_id`；事件 API 同时返回关联收款与流水 ID。无需改写原表或重新迁移历史数量。
- 备注重试复用请求键，成功后再次主动追加相同文字产生新事件；请求期间切换订单不会把旧响应写入另一个订单。
- `GET /api/orders/export` 复用列表全部筛选与排序，服务器分批导出全部匹配订单的商品明细，保留商品、收件快照及可靠业务时间。每商品明细一行，订单应收字段重复显示，汇总时须按订单 ID 去重；没有可靠来源的历史时间留空。CSV 继承 UTF-8 BOM、文本公式保护和鉴权。
- 常用筛选按当前账号保存在本浏览器，最多 20 个，可命名、使用、删除；不保留页码、打开的详情或概览快照边界。`/` 聚焦搜索，`Esc` 关闭非提交中的弹窗或详情，不在输入过程中触发搜索快捷键。
- 配货打印增加合并拣货汇总模式。仍对当前页最多 50 单统一校验，为每单保留文档与事件；汇总按商品 ID + 下单名称快照合并，避免同编码历史不同名称被覆盖。合并视图不含金额，并明确仍需逐单配货、复核。`/api/order-operations/print-jobs/{job_id}/html?layout=summary` 可查看该批次的固化来源汇总。
- 打印页提供带必填原因的“登记补打并打印”。每次打开打印对话框前调用 `/api/order-operations/print-jobs/{job_id}/validate` 核验最新状态，更新当前状态标识；取消/退款阻止新请求。历史页面直接通过浏览器打印时只显示需登记请求的提示，正文必须经过核验并有明确请求才能进入打印输出。取消打印仍只保留请求事件，不改变库存、订单状态或配送时间。
- 打印幂等键先在同事务中占用，再等待订单锁；相同请求并发重试返回同一任务、同一文档及同一事件。整批冲突时任务与所有明细回滚，选择保留；已有请求后调整打印内容会使用新请求键。

最终回归：48 项后端测试全部通过（含 7 项真实 MySQL 并发测试），34 项前端测试通过。浏览器在独立 `workbench-acceptance.sqlite` 上验证 110 条订单分页、详情深链接及前进后退、备注更正、CSV 110 行下载、常用筛选与快捷键、50 单生成 50 页、旧窗口补打登记、取消后拦截、50 单合并为一项拣货、60 行长商品名/地址/备注生成 10 页且无页脚覆盖，以及 390px 宽度；无页面运行错误。脚本及证据在 `.local-test/workbench-acceptance.mjs`、`.local-test/workbench-*-verified.*`，不写应用业务库。性能 P95 仍需按约定规模另做负载验收。
