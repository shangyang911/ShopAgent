# 运营 Copilot

入口为库存中心的“运营建议”，或 Agent 中的“智能补货 / 待发货分析”快捷问题。Agent 只选择分析工具；数量、订单条件和结果摘要由后端规则生成。模型无权通过这两个工具创建单据或修改库存。

## 智能补货

`GET /api/copilot/replenishment` 支持商品名称、备货覆盖天数（1–90）、安全比例（0–100%）、每 SKU 最低目标（0–10000）。仅分析可售商品的启用 SKU，每次最多500个，超出会明确提示缩小范围。

需求统计为近7/30天内收款、当前仍待发货/配送中/已完成的订单商品件数，取两个窗口日均需求的较高值。它是需求参考，非时间序列预测；不包含未付款/已取消/标记退款终态订单，也不根据部分退款金额推算件数。无需求历史时显示低置信提示和未知覆盖天数。

目标 = max(最低目标, ceil(日均需求 × 覆盖天数 × (1 + 安全比例)))。
新增草稿建议 = max(0, 目标 − 当前可售 − 同 SKU 已有入库草稿数量)。

可售库存已经扣除预留，因此不再重复减预留。已有草稿只用于避免重复计划；系统没有供应商交货承诺和预计到货日期，不能把草稿当成采购在途。库存覆盖天数只以当前可售计算。

核对流程：选择SKU → 核对数量并确认 → `POST /api/copilot/replenishment/draft` → 现有补货入库草稿 → 实物到货后由仓库按原流程确认。创建草稿不增加库存。后端锁定相关商品，复算建议、校验来源哈希和数量；数据变化返回409，需重新分析。幂等键用于响应丢失重试，同键不同内容被拒绝。草稿备注保留来源哈希用于核对。

## 待发货分析

`GET /api/copilot/shipping-analysis` 分析最多500笔当前已收款待发货订单，展示未登记主运单、处理中售后、最近面单任务失败/待核实、等待交接和收款后等待时长。原因可重叠，不以原因数相加冒充订单数。

仅有当前业务事实，没有历史队列快照，因此不会断言“今天比昨天积压增加”的真实根因。链接直接打开对应订单的发货工作台，仍执行原有交接、面单和售后校验。

## 验证

后端 `tests/test_copilot.py` 验证需求口径、不重复扣预留、草稿不动库存、幂等、过期建议、篡改数量、零历史与权限。前端回归验证参数改变阻止创建、重复点击防护、请求重试幂等键复用及旧响应隔离。Agent评测集v2增加两个场景、10条表述，合计70条离线任务；真实模型工具选择能力仍须单独运行live评测。
