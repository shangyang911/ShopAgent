## 当前接入状态

按本次选择，尚未申请快递100账号，正式环境没有注入演示轨迹。未配置时页面明确显示未接入实时查询，仍可使用高德和一期发货流程。平台轨迹的格式、签名、错误及业务联动已通过隔离测试；实际账号权限与真实运单的实网验收需在取得凭证后完成。

## 开通后配置

在 `backend/.env` 填写 `KD100_CUSTOMER` 和 `KD100_KEY`，然后重启后端。它们是快递100企业接口凭证，与高德 Key 不同，不要配置到 `VITE_` 前端变量。

- `LOGISTICS_AUTO_SYNC=false`：默认只在管理员点击“同步物流”时查询。填好凭证后可改为 `true`，开启后台定时轮询。
- `LOGISTICS_SYNC_INTERVAL_MINUTES=30`：同一实际运单至少间隔30分钟；设置更小值也会按30分钟执行，重复点击读取缓存。失败请求也遵守间隔。
- `KD100_CARRIER_CODES={}`：对自定义快递公司名称可添加官方编码映射，例如 `{"门店合作快递":"shunfeng"}`。内置一期常用公司的映射。公司名不能映射时会明确提示，不猜测物流商。

快递100查询要求运单号6至32位，部分物流商要求收件电话；一期保存的更长运单号会保留，但同步前会提示核对，不截断或擅自修改。

## 页面与业务规则

1. 发货详情下方查看物流记录，区分最新节点时间、最近成功同步时间、同步失败及保存的历史记录。暂无节点不等于已揽收或已签收。
2. 保存运单不会查询物流；实物交接后才允许查询。历史已发货的补录记录也可查；人工完成订单并不冒充快递签收。
3. 同步失败保留上次成功轨迹并标明待核实。重复节点去重；迟到的旧数据可补充历史节点，但不能覆盖更新的进度。平台时间按北京时间解析并存为UTC，无效时间保持未知。
4. 平台签收只更新物流事实，不自动完成订单。退回、退签不改变库存，实际退件仍需仓库验收。
5. 客服 `get_logistics` 工具只读取真实保存的记录，不触发外部付费查询。工具包含来源、成功同步时间、陈旧标记和错误；没有可信预计送达时间时不编造。最多提供最新16个节点，界面最多显示500个节点并标明是否截断。

## 技术边界

- 本期使用快递100主动查询及可选定时轮询，不要求公网回调地址；订阅推送/电子面单另行扩展。
- 主运单轨迹保存在 `shipment_tracking`、`shipment_tracking_events`；附加包裹轨迹保存在 `parcel_tracking`、`parcel_tracking_events`。已删除功能的待办表不再注册或创建。
- 同步先领取任务并释放数据库锁，之后才访问物流平台；返回时重新核对任务令牌和运单版本。不同公司别名也不能对同一实际运单重复查询。
- 后台只在账号已配置并显式启用时查询，每批最多20单；平台已签收的运单停止自动查询，仍可按间隔人工核实。
- 密钥不进入前端、轨迹记录、客服工具或错误提示。平台原始错误不直接转发，避免其回显敏感参数。

## 接口

- `GET /api/shipping/tracking-service`：返回服务是否配置、自动同步开关及查询间隔，不返回凭证。
- `GET /api/shipping/orders/{id}/tracking`：只读缓存、来源、时间线和同步状态。
- `POST /api/shipping/orders/{id}/tracking/sync`：按限频查询平台，返回 updated/cached/failed 结果；未配置或未交接时拒绝查询。

## 验证与来源

前端：`npm test`、`npm run build`、`npm run format:check`。

后端：`.venv\Scripts\python.exe -m unittest discover -s tests`。设置 `RUN_MYSQL_TESTS=1` 可在随机创建并清理的隔离MySQL库中验证并发交接和并发同步，只允许一个实际查询。

`.local-test/shipping-phase2-acceptance.mjs` 与 `.local-test/run-tracking-phase2.py` 是独立SQLite浏览器验收，平台模拟只存在于该测试进程，轨迹明确标为隔离验收响应，不写业务库。

接口签名、频率和参数依据[快递100实时查询官方文档](https://api.kuaidi100.com/document/5f0ffb5ebc8da837cbd8aefc.html)，公司编码参照[快递100官方编码说明](https://api.kuaidi100.com/document/kuaidiyugushixiaojiekouwendang)。
